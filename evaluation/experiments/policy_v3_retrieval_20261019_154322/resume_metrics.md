# 可用于简历的真实指标

以下表述只基于本次已经运行并保存的检索实验，不把关键词命中率写成准确率，也不声称最终回答质量已经提升。

## 推荐表述

- 基于 50 份售后政策草案构建 100-Chunk 隔离知识库和 66 题可追溯评测集，在独立 Docker/MySQL/Redis/FAISS 环境完成 4 组、共 264 次缓存旁路检索实验；固定 `candidate_k=10` 后，将 `final_k` 从 3 调整为 5，使 Evidence Hit@K 从 **83.33% 提升至 90.91%（+7.58 个百分点）**，宏平均来源 Recall@K 从 **65.40% 提升至 75.51%（+10.10 个百分点）**。

- 设计并验证控制变量实验，确保四组配置在 **66/66 道题**上的 FAISS 初始候选完全一致；记录逐题候选、排序、来源、分数、索引哈希与分阶段耗时，实现 experiment/run/case_run 三级追踪和可复算指标产物。

- 评估 `BAAI/bge-reranker-base` 精排效果，发现当前阈值组合使 Evidence Hit@3 从 **83.33% 降至 78.79%**，并将服务端平均检索耗时从 **18.26 ms 增至 1628.28 ms**；据真实实验结果选择无精排、`final_k=5` 作为本轮最佳检索配置，并识别出精排阈值需要单独校准。

## 一句话版本

在 50 份政策、100 个 Chunk、66 道题的隔离 RAG 评测中完成 264 次可追溯参数实验，通过将最终证据数从 3 调整到 5，把来源级 Evidence Hit@K 从 83.33% 提升到 90.91%（+7.58 个百分点），宏平均 Recall@K 从 65.40% 提升到 75.51%（+10.10 个百分点）。

## 使用边界

- 应写“来源级证据命中/召回”，不要写“回答准确率提升”。
- 应注明这是基于 V3 政策草案的探索性离线评测。
- 当前没有真实 LLM 最终回答、关键词得分、Faithfulness、Token 或成本数据。
- 不建议把 A/B 之间几毫秒的差异写成性能优化；实验没有随机化或重复轮次。
- Rerank 负向结果同样有价值：它证明项目通过实验选择参数，而非凭经验默认启用精排。
