# Policy V3 最终回答质量对比实验报告

## 1. 结论

本实验在隔离评测环境中，对同一批 66 道 Policy V3 草案题目分别运行两组真实 DeepSeek 回答生成，共完成 132 次请求，全部成功，没有重试、跳过或缓存命中。

| 指标 | A：candidate_k=10, final_k=3 | B：candidate_k=10, final_k=5 | B 相对 A |
|---|---:|---:|---:|
| 题目数 | 66 | 66 | 相同 |
| 关键词宏平均分 | 58.08% | 63.51% | +5.43 个百分点；相对 +9.35% |
| 必需事实微平均覆盖率 | 85.81%（133/155） | 92.90%（144/155） | +7.10 个百分点；相对 +8.27% |
| 严格语义通过率（Codex 逐题复核） | 71.21%（47/66） | 84.85%（56/66） | +13.64 个百分点；相对 +19.15% |
| 严格无答案题正确克制 | 100%（8/8） | 100%（8/8） | 持平 |
| 需要澄清题行为正确 | 100%（3/3） | 100%（3/3） | 持平 |
| 错误拒答 | 0/66 | 0/66 | 持平 |
| 禁止断言命中 | 0/66 | 0/66 | 持平 |
| 平均端到端耗时 | 1611.59 ms | 1548.11 ms | -63.48 ms；相对 -3.94% |
| 中位端到端耗时 | 1571.95 ms | 1536.86 ms | -35.09 ms；相对 -2.23% |
| P95 端到端耗时 | 1988.85 ms | 1948.37 ms | -40.48 ms；相对 -2.04% |
| 平均 Context 长度 | 1525.95 字符 | 2534.92 字符 | +66.12% |
| 总 Tokens | 77,789 | 114,149 | +46.74% |
| 峰值费率估算费用 | ¥0.193840 | ¥0.270322 | +39.46% |

在本次样本、模型和单轮运行条件下，B 的回答完整性更好，并未观察到延迟上升；但 B 使用的 Context 和输入 Tokens 明显更多。延迟下降只有一次配对运行样本，容易受到网络和提供商服务状态影响，不能据此概括为 `final_k=5` 必然更快。

## 3. 调用与费用

第一条正式请求成功后才继续批量执行。该请求实际使用输入 1,164、输出 108，共 1,272 Tokens，费用估算 ¥0.003192。完整实验的 provider attempt 连续覆盖 1–132，不存在重试或遗漏。

总用量为输入 178,557、输出 13,381，共 191,938 Tokens。按实验时记录的峰值费率（输入 ¥2/百万 Tokens，输出 ¥8/百万 Tokens）估算为 **¥0.464162**，低于授权上限 ¥1.50。这里是按实际 Token usage 与公开费率计算的估算值，不等同于提供商账单结算记录。

## 4. 指标口径

### 4.1 关键词分

完全复用现有系统口径：逐题计算“答案中直接出现的预期关键词数 / 预期关键词总数”，再对 66 题取宏平均。该指标只衡量字符串命中，不检查事实关系、否定语义或条件完整性，因此不能称为回答准确率。

### 4.2 必需事实覆盖率

依据每题 `required_facts`，逐条核对生成回答是否表达该事实。汇总采用微平均：覆盖的事实单元数 / 全部事实单元数。A 为 133/155，B 为 144/155。

### 4.3 严格语义通过率

每题必须覆盖全部 `required_facts`，且不包含 `forbidden_claims` 所描述的错误结论，才标记为严格通过。A 有 47 题严格通过、19 题部分正确；B 有 56 题严格通过、10 题部分正确。本轮没有发现完全错误或违反禁止断言的回答。

逐题判断及缺失事实保存在 `manual_semantic_review.jsonl`。这是一轮由 Codex 执行的逐题语义审阅，**不是独立人类或业务专家复核**。因此 71.21% 和 84.85% 可作为可审计的初步严格语义指标，但不得对外表述成“经人工验收的真实准确率”。可靠的人类准确率仍需要至少一名熟悉政策的审核者确认逐题标签；最好采用双人独立标注和争议仲裁。

### 4.4 拒答与澄清

- 严格无答案题：8 题。两组均能说明知识库无法支持确定结论并保留人工核实路径，正确克制为 8/8。
- 需要澄清题：3 题。两组均识别信息不足或语义冲突并要求澄清/复核，为 3/3。
- 错误拒答：两组均为 0。这里的“错误拒答”指对有证据问题完全拒绝提供任何可支持结论；部分事实遗漏记为“部分正确”，没有混入错误拒答。

## 5. 哪些问题因 final_k=5 改善

B 组相对 A 组新增完整覆盖的典型问题包括：

- `PDV2-C004`：补充预览、确认与申请创建的流程边界。
- `PDV2-C011`：补充商品完好、配件包装齐全及不影响二次销售。
- `PDV2-C015`：明确区分 7 天无理由与 30 天质量问题路径。
- `PDV2-C025`：补充人工核查所需的订单号、退款记录、发起时间和支付渠道。
- `PDV2-C034`：补充复现条件、日志/视频和人工复核。
- `PDV2-C042`：明确键盘等其他外设不得套用 30 天规则，应转人工。
- `PDV2-C048`：区分已使用商品的无理由路径与质量问题路径。
- `PDV2-C055`：直接说明 Rerank 相关度排序不决定政策效力。
- `PDV2-C061`：补充鼠标双击信息提交和人工审核。

两组共同存在的主要遗漏包括：预览确认后的执行前复核、`pending` 的准确含义、业务系统订单状态判断、多轮信息的完整语义保留、第 8 天仍可咨询其他权利、25 天故障处于 30 天候选路径、耳机单侧无声的完整排查项、`delivered_at` 的业务数据库核验，以及运输损坏的完整证据清单。

## 6. 检索与回答指标的关系

上一轮检索实验中，A 的 Evidence Hit@K 为 83.33%，B 为 90.91%；本轮回答实验使用相同 A、B 参数。回答侧的必需事实覆盖率同步从 85.81% 上升到 92.90%，说明增加最终证据数量在这批题上确实带来了更多必要条件。但这不是因果证明：同一模型具有生成随机性，且当前仅运行一次。

本轮“标注来源命中率”同样为 A 83.33%、B 90.91%，与上一轮检索结果一致。来源精确率没有用来评价回答正确性，因为答案可能引用数据集未列为首选、但仍然相关的政策；把这些额外来源一律计错会低估实际依据质量。

## 7. 可复现性与安全检查

- 评测数据库中两个 run 均真实保存 66 条 Case Run。
- 独立评测 Redis 的运行时 `DBSIZE` 为 0。
- 132 条记录的索引清单哈希完全一致，实验没有修改或重建共享索引。
- 独立评测 MySQL、Redis 和 FAISS 使用 `rag-evaluation` 资源；评测 API 只发布在 `127.0.0.1:18080`。
- 智能客服的 Backend、Frontend、Policy RAG、MySQL、Redis 和 Admin Workbench 在实验后仍全部 healthy。
- API Key 只通过容器环境注入，未写入代码、Compose 或实验产物。
- 缓存旁路与 Policy RAG 契约目标测试在评测容器内运行 16 项，全部通过。宿主 Python 缺少 NumPy/Pytest，B3 测试与 tracking v2 全套测试未在宿主环境重跑；容器内 tracking 测试因镜像未包含迁移 SQL 文件而无法完整执行，这不是业务断言通过。

## 8. 限制

1. 50 份政策和 66 道题仍是 V3 草案，题目多数标记 `needs_human_review`；结果只代表草案快照。
2. 严格语义通过率尚未由独立人类审核者确认，不能称为最终人工准确率。
3. 每组只运行一次；LLM 生成和外部服务延迟具有随机性，尤其不能把单次延迟差异概括为稳定性能提升。
4. 两组均关闭 Rerank，本报告不支持“Rerank 改善最终回答”的结论。
5. B 的质量完整性更高，但输入 Tokens 增加 50.04%，总 Tokens 增加 46.74%，应在质量与成本之间权衡。
6. 本轮没有修改正式业务代码、正式数据库、正式 Redis、共享 FAISS 或智能客服服务。

## 9. 推荐结论

对于这批 Policy V3 草案题目，`candidate_k=10, final_k=5, rerank=false` 是两组中更合适的回答质量配置：客观关键词分、逐项必需事实覆盖和初步严格语义通过率均更高，且无答案与澄清行为没有退化。代价是 Context 增长 66.12%、总 Tokens 增长 46.74%、估算费用增长 39.46%。在写入对外材料前，应完成独立人类复核；在部署决策前，应增加多次重复实验验证延迟和生成稳定性。
